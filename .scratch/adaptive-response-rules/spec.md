# Botmux 全局自适应回复规则

状态：待用户确认测试 seam 后进入实现。

## Problem Statement

Botmux 的不同机器人和 CLI 对问答、任务进度、错误和最终结果采用不同的表达方式。用户常需要从较长回复中自行寻找结论、当前状态、验证证据和下一动作。逐 CLI 安装 `i-have-adhd` 等技能又会形成多条装配与升级链路，导致新机器人漏配和行为漂移。

## Solution

在 Botmux 公共角色层维护一份跨 CLI 的自适应回复规则，供当前及未来所有机器人、面向所有用户使用。规则吸收 `i-have-adhd` 的行动导向结构和 `wait-what` 的必要上下文、短句与统一术语原则，但不机械套模板，也不全局强制 ASD-STE100。现有安全、审批、交付和岗位规则保持更高优先级。

## User Stories

1. 作为 Botmux 用户，我希望第一行看到结论或第一动作，以便立即理解当前结果。
2. 作为 Botmux 用户，我希望多步骤任务被拆成有边界的编号步骤，以便逐项执行。
3. 作为长任务发起人，我希望每次进度都重述当前阶段，以便不用记住上一轮状态。
4. 作为长任务发起人，我希望只收到有信息增量的阶段进度，以便避免无意义刷屏。
5. 作为任务发起人，我希望估时使用分钟、小时或明确条件，以便判断等待成本。
6. 作为任务发起人，我希望最终汇报区分已保存、已验证、已发布和已部署，以便准确判断是否生效。
7. 作为任务发起人，我希望重要结果附必要证据，以便核验完成声明。
8. 作为任务发起人，我希望剩余风险明确列出，以便决定是否继续推进。
9. 作为遇到错误的用户，我希望看到失败位置、现象、已知原因和下一诊断动作，以便继续处理。
10. 作为普通用户，我希望简单问题得到简单回答，以便不被固定模板增加阅读负担。
11. 作为需要详细解释的用户，我希望机器人可以完整展开，同时保持标题、短句和术语一致。
12. 作为项目成员，我希望机器人使用项目词汇表中的名称，以便不同回复指向同一概念。
13. 作为文件接收者，我希望回复风格不会掩盖附件是否真实送达，以便避免误判交付完成。
14. 作为生产操作审批者，我希望行动导向规则不会跳过确认，以便保持安全边界。
15. 作为 Reviewer，我希望自测和独立验收被清楚区分，以便质量结论可信。
16. 作为 DevOps，我希望未部署的改动不会被写成已生效，以便运行状态准确。
17. 作为 Botmux 维护者，我希望所有 CLI 从同一公共正本继承规则，以便减少版本漂移。
18. 作为 Botmux 维护者，我希望新增机器人自动继承规则，以便避免逐席配置。
19. 作为 Botmux 维护者，我希望上游技能更新经过人工评估和 A/B 验证，以便避免未知规则自动进入运行环境。
20. 作为 Botmux 维护者，我希望发布前保留精确回滚点，以便恢复本次受影响的公共规则。
21. 作为产品决策者，我希望全量启用后观察三天，以便用真实对话决定保留、修改或回滚。
22. 作为产品决策者，我希望任何回滚都由我确认，以便控制全局行为变更。

## Implementation Decisions

- 单一正本位于 Botmux 公共角色装配层，不在各 CLI 独立安装完整技能。
- 公共规则覆盖当前及未来所有 Botmux 机器人，并面向所有用户生效。
- 规则按任务自适应：简单回复保持一句，多步骤任务才编号，解释型请求允许充分展开。
- 第一行在进行中任务中优先给第一动作，在完成或状态查询中优先给结论。
- 长任务只在有效开始、阶段完成、新风险或阻塞、需要决策时发送进度。
- 重要最终汇报包含结论、必要证据、生效状态和剩余风险；有真实待办时只给一个下一动作，没有待办时直接结束。
- `wait-what` 的必要上下文、短句、主动语态和统一术语进入公共规则；完整 ASD-STE100 不作为全局要求，显式 `/wait-what` 仍可用于重新表述。
- 安全确认、生产审批、文件交付、岗位边界和独立审查高于回复风格规则。
- 普通用户没有会话级关闭开关；关闭或回滚通过版本化公共配置完成。
- 上游技能版本固定记录，更新通过人工差异审查和受控 A/B 验证，不自动覆盖。
- 一次全量启用，发布前保存 team、profile 和群覆盖的旧值、哈希和更新时间。
- 发布后观察三天；发现问题先保存证据并请求用户决定，未获确认不执行回滚。

## Testing Decisions

- 最高测试 seam 是“最终角色注入 → 真实飞书回复”，验证用户可见行为，不钉提示词内部措辞。
- 配置 seam 验证公共正本经渲染后进入每个当前席位，哈希一致，重复装配幂等，他群业务约束不变。
- Ticket 01 只关闭代表席实现与独立代码审查；真实运行行为在 Ticket 03 全量发布后验收，迁移不代表已通过。
- 当前每个机器人至少完成一次真实飞书回复测试，证明没有漏配。
- 岗位与 CLI 代表席覆盖普通问答、执行进度、最终结果、错误阻塞和简单确认五类场景。
- 高优先级回归验证：破坏性操作仍先确认；未发布不称已生效；自测不称独立验收；附件未送达不称交付完成；岗位边界保持不变。
- 测试断言外部行为与状态，不固定文案、内部常量或源文件文本。
- 静态渲染通过不能替代真实会话验收；单个代表席通过不能推断全员生效。
- 发布报告分别记录源文件已保存、运行配置已应用、新会话已加载和真实回复已验证。

## Out of Scope

- 不改变模型、思考等级、网关、额度、工具权限或会话后端。
- 不改变岗位职责、派工、审查或生产操作授权。
- 不诊断或治疗 ADHD，也不推断用户健康状况。
- 不要求每条回复使用标题、清单或固定字段。
- 不自动同步上游技能更新。
- 不保证发布前已经存在的模型调用中途加载新规则。
- 本 spec 不执行部署、服务重启或回滚。
